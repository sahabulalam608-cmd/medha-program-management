1 Publish the site (free hosting)

The site folder you received contains index.html plus an assets folder, a backend folder and a docs folder. It is already built — there is nothing to compile.

Do this one thing carefully The folder you drop must have index.html sitting directly inside it. If you drop a folder that contains a sub-folder called mpm-site, the site will 404. Open the folder first and check that index.html is the first thing you see.

Option A — Netlify Drop (fastest, recommended)

1 Unzip the download on your computer
Open mpm-site-source.zip and extract it. You now have a folder called mpm-site — or mpm-site-source, whichever your unzip tool names it.
2 Open the drop page
Go to app.netlify.com/drop.
3 Sign in (free)
Click Sign up and log in with Google — same account as your Sheets. You need an account, otherwise the site is temporary and gets deleted.
4 Drag the folder onto the box
Drag the whole folder (with index.html directly inside) onto the purple drop area. Wait about ten seconds.
5 Copy your address
You get a link like https://your-name-1234.netlify.app. Open it — the portal appears.
6 Give it a proper name
Click the site name in the Netlify dashboard → Change site name → type something like medha-program. Your address becomes https://medha-program.netlify.app.
Updating later Keep the folder on your computer. When something changes, drag the same folder onto the drop zone again — from your Netlify dashboard, the bottom of the site page has the drop zone. The new version replaces the old one and your address stays the same.

Option B — Cloudflare Pages (best free speed, unlimited bandwidth)

  1. Go to dash.cloudflare.com and sign in.
  2. Workers & Pages → Create → Pages → Upload assets.
  3. Name the project medha-program, then drag the same folder (or the zip — Cloudflare accepts it) onto the upload area.
  4. Your address: https://medha-program.pages.dev.

Option C — Firebase Hosting (same Google account)

  1. Go to console.firebase.google.com → Add project (use your existing Google account).
  2. Hosting → Get started → pick the project.
  3. Run firebase login and firebase deploy --only hosting from the folder, or use the Hosting console's manual upload.
  4. Your address: https://<project>.web.app.

Free tier: 10 GB of storage and 10 GB of traffic per month. Plenty for an internal portal. No credit card needed.

Option D — GitHub Pages

  1. Create a repository (public) and upload the folder's contents.
  2. Settings → Pages → Source: Deploy from a branch → main / root → Save.
  3. Your address: https://<you>.github.io/<repo>.
One note on GitHub Pages GitHub's terms say Pages is not meant for sites that mainly handle sensitive transactions such as passwords. MPM's login is only a front-door gate and the real work happens in your own Google account, but Netlify, Cloudflare or Firebase are the safer choice if you want to avoid that grey area.

2 Connect the backend (one Apps Script, both sheets)

Without this step the portal still shows every member, every score and every result card — it is simply read-only. With it, mail sending, attendance marking, score saving, agreement saving, Drive uploads and emailing result cards all switch on.

You only need ONE Apps Script project Even though your data lives in two separate Google Sheets, a single Apps Script project reaches both of them. The backend opens each one by its spreadsheet ID, so the sheet the script is attached to does not matter. Paste the code once, deploy once, paste one URL into the portal — both sheets work.

The exact steps

1 Open the backend file
In your site folder there is backend/Code.gs. Open it in a text editor and select everything (Ctrl + A) and copy it (Ctrl + C).
2 Create ONE project
Go to script.google.com → New project. Do not choose "New from spreadsheet" — a standalone project can reach both sheets.
3 Paste the code
Click Code.gs in the editor, select all, paste. Save (Ctrl + S). Rename the project to something like Medha Program Backend.
4 Set the time zone (and optionally the three IDs)
Project Settings (gear icon) → set Time zone to Asia/Dhaka.

Script Properties is optional — the IDs are already inside the code. If you add them, add all three and paste them rather than typing: 
SHEET_ID        = 1f1lPFlXA8tRXtg5GfyetufaUYHYnZPn9AfCHiOwZwII
NCM_SHEET_ID     = 1DIcYeYPIascTRDhthEq2fG5kCAtL_-t4_kbu5n-pDmE
BATCH01_SHEET_ID = 1PZ4Ccbec-Qm5m_s4mFya_X24Ykd9HGgw0Mcmfpf9zZw
If you are not sure a value is typed exactly right, delete that property — the code then uses the ID it already carries.
5 Run the one-time setup
At the top of the editor choose the function setupProgramSheets from the dropdown → click Run. Approve the permission prompt ("Google hasn't verified this app" → Advanced → Go to (project name) → Allow). It creates the Agreements tab and the Status dropdown, and reports what it did.
6 Deploy as a web app
Deploy → New deployment → gear icon → Web app:
  • Description: Medha Program Management
  • Execute as: Me (your own account)
  • Who has access: Anyone — this is what lets the portal reach it from the browser
Click Deploy and copy the Web app URL (it ends in /exec).
7 Paste it into the portal
In the portal click the … button at the bottom of the left sidebar → enter the combination 2026 on the dial → click Connect backend → paste the URL → Save.
8 Give the script permission to read Gmail
The Mail portal's Inbox reads the real Gmail of the account that owns the script (otanextchaptermastermind@gmail.com). For that the script needs the Gmail permission:
  • Project Settings (gear) → tick Show “appsscript.json” manifest file in editor → open the file → replace it with the backend/appsscript.json from this folder → save.
  • Back in the editor choose the function setupGmail from the dropdown → Run.
  • Approve the Gmail permission (Advanced → Go to (project name) → Allow).
  • Deploy → Manage deployments → edit the web app → Version: New version → Deploy. The URL does not change.
After this the Inbox shows your real mails, the unread count is real, and a mail turns read only when you open it.
Done The sidebar badge changes from Read-only to Backend connected, and the sheet is now the single source of truth: write in the portal and the sheet updates, write in the sheet and the portal updates within 30 seconds.
If you ever change the code After editing Code.gs you must create a new deployment version (Deploy → Manage deployments → edit → Version: New version). Editing the code does not change the live URL on its own.

4 A few things worth knowing

  • The sheet is the source of truth. The portal is a fast window onto it. Anything you do in either place shows up in the other.
  • Mobile numbers are shown with the leading 0. The sheet stores them as plain numbers (1734806516); the portal displays them correctly (01734806516) everywhere — card, profile, payments, DOCX. The sheet value is never altered.
  • Scores you type without the backend stay in your browser as a draft, and you can export them as CSV from the same page to paste into the sheet. Connecting the backend makes them save straight to the tracker.
  • Everything is stored in your own accounts. The website is only the front end; the data lives in your Google Sheets and your Google Drive. Nothing is hosted on anyone else's database.
  • Reaching the whole team — give them the address and the portal login. The second login is ota / ota2026 for read-only staff.
